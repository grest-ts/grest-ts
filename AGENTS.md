# AGENTS.md

## Cursor Cloud specific instructions

### Overview

grest-ts is a TypeScript framework monorepo using **npm workspaces**. All `package.json`, `tsconfig.json`, and `vitest.config.ts` files are auto-generated by `npm run generate` (runs `tsx grest.package.ts`). Do not edit these generated files directly.

### Prerequisites (pre-installed in snapshot)

- **Node.js 25** via nvm (default alias set to 25; activated in `~/.bashrc` and `~/.zshrc`)
- **PostgreSQL 16** with user `postgres` / password `postgres` on `localhost:5432`
- Databases `checklist` and `blocker` initialized from `examples/checklist/*/schema/*.postgres.sql`

### Starting PostgreSQL

PostgreSQL may not be running after a VM restart. Start it with:

```bash
sudo pg_ctlcluster 16 main start
```

### Key commands

All commands are run from the workspace root. See `package.json` `scripts` and `CONTRIBUTING.md` for the full list.

| Task | Command |
|------|---------|
| Install dependencies | `npm install` |
| Regenerate configs | `npm run generate` |
| Type check | `npm run typecheck` |
| Full check (generate + typecheck + examples) | `npm run check` |
| Run all tests | `npm test` |
| Run tests in watch mode | `npm run test:watch` |
| Run specific package tests | `npm test -- packages/http` |

### Testing notes

- Core package tests are pure unit tests (no external services).
- `examples/grest-test` integration tests spin up runtimes in-process — no database needed.
- `examples/checklist` tests require PostgreSQL running with `checklist` and `blocker` databases initialized. The test framework uses `GGPostgresSchemaCloner` to clone schemas per-suite for isolation.
- MySQL is optional and only used as an alternative DB backend in the checklist example.

### Gotchas

- The `util._extend` and `url.parse()` deprecation warnings from Node 25 are harmless and expected.
- After modifying package structure or adding packages, run `npm run generate` to regenerate all config files before committing.
